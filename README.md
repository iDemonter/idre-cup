# Idre Cup

Приложение для iPhone: недельное соревнование друзей на горнолыжном курорте Idre Fjäll.
Рейтинг по GPS, короны трасс, дуэли, вечерние игры.

Состояние: **шаг 1 из 5**. Приложение показывает рельеф Apple Maps над Idre Fjäll, сервер умеет отвечать на проверку здоровья и отдавать правила.

## Что где лежит

| Папка | Что внутри |
|---|---|
| `app/` | Приложение на SwiftUI. Проект Xcode в репозитории не хранится, его создаёт XcodeGen из `app/project.yml`. |
| `server/` | Сервер: Node, Postgres, Docker. Считает очки по сырым трекам. |
| `.github/workflows/ios.yml` | Сборка и отправка в TestFlight. |

## Сборка приложения

Mac для разработки нет, всё собирает GitHub Actions на `macos-26`.

- **Проверочная сборка** запускается на каждый коммит в `app/`. Компилирует под симулятор, секреты не нужны.
- **TestFlight** запускается для ветки `main`: архив, подпись облачным сертификатом Apple, отправка. Если секреты не заданы, шаг пропускается с пояснением.

Номер сборки берётся из номера запуска, вручную его менять не нужно.

### Секреты репозитория

Settings → Secrets and variables → Actions → New repository secret.

| Секрет | Что это | Где взять |
|---|---|---|
| `ASC_KEY_ID` | ID ключа App Store Connect API | App Store Connect → Users and Access → Integrations → App Store Connect API |
| `ASC_ISSUER_ID` | Issuer ID | там же, над списком ключей |
| `ASC_KEY_P8` | Содержимое файла `AuthKey_XXXX.p8` целиком | скачивается один раз при создании ключа |
| `APPLE_TEAM_ID` | Team ID, 10 символов | developer.apple.com → Account → Membership details |

Ключу нужна роль **Admin**: только с ней Apple разрешает подпись облачным сертификатом распространения.

В коде секретов нет и быть не должно: репозиторий публичный.

### Идентификатор приложения

`com.idemonter.idrecup`. Он должен быть зарегистрирован в Certificates, Identifiers & Profiles, и для него должна быть создана запись приложения в App Store Connect.

## Трассы на карте

Линии трасс и подъёмников взяты из OpenStreetMap, номера, зоны и сложность из официальной карты трасс Idre Fjäll 2026/27.

- `data/osm-idre.json` — сырые данные OpenStreetMap. Обновляет workflow «Данные трасс» (`tools/fetch_osm.py`).
- `tools/build_pistes.py` — собирает из них `app/IdreCup/Resources/pistes.json`, который читает приложение.

На карте все 41 трасса. По названию в OpenStreetMap находятся 35, остальные сопоставлены вручную в `tools/build_pistes.py`:

- 39 Glidaren, 40 Gondolsvängen и низ 41 Pernillabacken: в OpenStreetMap это линии без названия, номер назначен по положению (таблица `UNNAMED`).
- 7 Äventyret и 8 Snowpark: в OpenStreetMap записаны как «Snowpark röd» и «Snowpark grön/blå» (таблица `ALIASES`).
- 2 Familjeparken и 3 Askes skidområde: в OpenStreetMap их нет, нарисованы от руки (таблица `DRAWN`). На карте они пунктирные, точность 30–50 м.

Сопоставление по положению стоит проверить на месте.

Данные карты: © участники OpenStreetMap, лицензия ODbL.

## 3D-модель горы

Вид «Модель» рисует гору сам, без Apple Maps: сетка высот, раскраска с тенями и горизонталями, на ней трассы и подъёмники. Высота вытянута в 2,6 раза, потому что гора пологая. Работает без интернета.

- `data/dem-idre.json` — высоты района. Обновляет workflow «Данные высот» (`tools/fetch_dem.py`).
- `data/osm-land.json` — вода, дома, дороги и полезные места из OpenStreetMap. Обновляет workflow «Данные трасс».
- `tools/build_terrain.py` — собирает в `app/IdreCup/Resources/` три файла: `terrain.json` (сетка 25 м), `terrain.jpg` (раскраска: высота, тени, горизонтали, лес, дороги, вода) и `scenery.json` (деревья, дома, полезные места, районы посёлка). Нужны numpy, scipy и Pillow.
- `app/IdreCup/Scenery.swift` — объёмные ели и домики. Лес расставлен по высоте (ниже 790 м сплошной, выше 850 м его нет): в OpenStreetMap он отмечен не везде.
- `app/IdreCup/TerrainView.swift` — сцена SceneKit.

Высоты: Copernicus DEM GLO-30. © DLR e.V. 2010-2014 и © Airbus Defence and Space GmbH 2014-2018, предоставлены по программе COPERNICUS Европейским союзом и ESA; все права защищены.

## Трекинг

- `Tracker.swift` — запись GPS раз в секунду, в том числе в фоне. Трек дня дописывается в файл на телефоне (`TrackStore`), поэтому не теряется без связи и при закрытии приложения.
- `TrackAnalyzer.swift` — разбор трека: сглаженная высота, развороты вверх и вниз, между ними спуски и подъёмы. Скорость засчитывается, если держалась 3 секунды. Пороги лежат в `TrackRules`.
- `MyDayScreen.swift` — экран «Мой день»: скорость, перепад, спуски, дистанция, список спусков и подъёмов.
- `DemoTrack.swift` — демо-день: выдуманный трек по трассам Nord, чтобы проверить подсчёт без горы.

Пока трек считается на телефоне и никуда не отправляется. Спуском считается любой спуск от 20 м по высоте, где бы он ни был: ограничение территорией курорта и подсчёт на сервере появятся на шаге 2.

## Кубок и рейтинг

- `Session.swift` — связь с сервером: вход, участники, отправка треков раз в полминуты, аватары. Токен устройства лежит в связке ключей.
- `RatingScreen.swift` — вход по коду или создание кубка, рейтинг дня и общий зачёт.
- `ProfileScreen.swift` — профиль, аватар (фото или Image Playground), код приглашения, участники, настройки админа.
- `config/app.json` — адрес сервера. Приложение читает его при запуске, поэтому сервер можно перенести без новой сборки.

## Снимки экрана

Каждая сборка запускает приложение в симуляторе и кладёт снимки экрана в ветку `screenshots` (она перезаписывается). Вид, зону, раздел и демо-день можно задать параметрами запуска: `-look Модель -preset Nord -section day -demo YES`. Для экранов кубка сборка поднимает сервер с демо-кубком (`server/tools/seed-demo.js`) и передаёт приложению `-serverURL` и `-token`.

Node + Postgres в Docker. Как поставить и обновлять: [server/deploy.md](server/deploy.md).

```bash
cd server
npm install && npm test       # проверки без базы
```
